
================================================================================
SECTION 1: LEAD MANAGEMENT OVERVIEW
================================================================================

Lead Flow:
1. Create Lead → 2. Manage Lead → 3. Track Events → 4. Convert to Vendor

Lead Statuses:
- new: Just created, not yet contacted
- contacted: Initial contact made
- engaged: Active discussions
- converted: Successfully converted to vendor
- rejected: Not interested/qualified

Lead Priorities:
- low, medium, high, urgent

IMPORTANT:
- Each lead can be assigned to a salesman
- Events track all interactions with the lead
- Converting a lead automatically creates a vendor account
- Conversion records track commission and value

SECTION 8: LEAD CONVERSION
================================================================================

Converting a lead means turning it into an actual customer (vendor). There are two
approaches:

8.1 CONVERT LEAD TO VENDOR (Automatic Creation)
================================================================================

API ENDPOINT:
POST http://localhost:3000/api/v1/leads/convertLeadToVendor

HEADERS:
Authorization: Bearer {token}
Content-Type: application/json

REQUEST BODY:
{
  "lead_id": "lead-uuid",
  "broker_id": "broker-uuid",  // optional
  "conversion_value": 500000,  // optional
  "commission_rate": 2.5,      // optional (percentage)
  "notes": "Converted after successful negotiation"  // optional
}

REQUIRED FIELDS:
- lead_id (uuid)

OPTIONAL FIELDS:
- broker_id (uuid, if broker was involved)
- conversion_value (number, deal value)
- commission_rate (number, percentage for commission calculation)
- notes (string, conversion notes)

WHAT THIS ENDPOINT DOES:
1. Creates a new user account for the vendor
   - username = email prefix (before @)
   - email = lead's email
   - password = "defaultPassword123" (should be changed)
   - full_name = lead's contact_person
   - phone = lead's phone
   - user_type = "vendor"
   - is_active = true

2. Creates a new vendor record
   - business_name = lead's company_name
   - contact_person = lead's contact_person
   - email = lead's email
   - phone = lead's phone
   - address = lead's address
   - business_details = lead's business_details
   - type = "both" (can purchase and sell)
   - is_active = true
   - user_id = newly created user's id
   - lead_id = original lead's id

3. Creates a conversion record
   - Links lead to the new vendor
   - Stores conversion_value and commission_rate
   - Calculates commission_amount = (conversion_value * commission_rate) / 100
   - Stores notes and broker_id

4. Updates lead status
   - lead_status = "converted"
   - customer_status = "active"
   - is_existing_customer = true

5. Creates a conversion event
   - event_type = "converted"
   - Stores vendor_id and conversion_id in metadata

SUCCESS RESPONSE (201):
{
  "success": true,
  "message": "Lead converted to vendor successfully",
  "data": {
    "conversion": {
      "id": "uuid",
      "lead_id": "lead-uuid",
      "vendor_id": "vendor-uuid",
      "broker_id": "broker-uuid",
      "conversion_date": "2025-10-27T12:00:00.000Z",
      "conversion_value": 500000,
      "commission_rate": 2.5,
      "commission_amount": 12500,
      "created_by": "admin-uuid",
      "notes": "Converted after successful negotiation"
    },
    "vendor": {
      "id": "vendor-uuid",
      "business_name": "ABC Corporation",
      ...
    }
  },
  "timestamp": "..."
}

ERROR RESPONSES:
- 404: Lead not found
- 409: Lead is already converted
- 400: Validation error

EXISTING CUSTOMER HANDLING:
If lead.is_existing_customer = true and a vendor with the same email exists:
- Links to existing vendor instead of creating new one
- Creates conversion record to link the lead to existing vendor
- Does not create duplicate user

IMPLEMENTATION:
1. Show "Convert to Vendor" button on lead detail page
2. Open conversion dialog with fields:
   - Conversion Value (number input)
   - Commission Rate % (number input)
   - Broker Selection (dropdown from /brokers/getAllBrokers)
   - Notes (text area)
3. On submit: Call API
4. On success: Show success message, redirect to vendor detail page
5. Update lead status in UI to "converted"

11.1 API SERVICE STRUCTURE

// api/leads.js
export const leadsAPI = {
  getAll: (filters) => {
    let url = `${API_BASE_URL}/leads/getAllLeads`;
    const params = new URLSearchParams();
    if (filters.lead_status) params.append('lead_status', filters.lead_status);
    if (filters.assigned_to) params.append('assigned_to', filters.assigned_to);
    if (filters.priority) params.append('priority', filters.priority);
    if (filters.is_existing_customer !== undefined) params.append('is_existing_customer', filters.is_existing_customer);
    if (params.toString()) url += `?${params.toString()}`;
    return axios.get(url);
  },
  
  getById: (id) => 
    axios.get(`${API_BASE_URL}/leads/getLeadById/${id}`),
  
  create: (data) => 
    axios.post(`${API_BASE_URL}/leads/createLead`, data),
  
  update: (id, data) => 
    axios.post(`${API_BASE_URL}/leads/updateLead/${id}`, data),
  
  delete: (id) => 
    axios.post(`${API_BASE_URL}/leads/deleteLead/${id}`),
  
  getEvents: (id) => 
    axios.get(`${API_BASE_URL}/leads/getLeadEvents/${id}`),
  
  addEvent: (data) => 
    axios.post(`${API_BASE_URL}/leads/addLeadEvent`, data),
  
  convertToVendor: (data) => 
    axios.post(`${API_BASE_URL}/leads/convertLeadToVendor`, data),
  
  convert: (data) => 
    axios.post(`${API_BASE_URL}/leads/convertLead`, data),
  
  getAnalytics: () => 
    axios.get(`${API_BASE_URL}/leads/getLeadAnalytics`)
};

SECTION 13: IMPORTANT NOTES
================================================================================

1. Lead Events are automatically created when:
   - Lead is created (created event)
   - Status changes (status_changed event)
   - Assignment changes (assigned event)
   - Lead is converted (converted event)

2. Converting a lead to vendor:
   - Automatically creates user account with default password
   - Creates vendor record with lead data
   - Updates lead status to "converted"
   - Creates conversion record for tracking
   - Cannot be undone

3. Lead assignment:
   - Only assign to users with user_type = "salesman"
   - Use /salesmen/getAllSalesmen to get valid salesmen
   - Assignment can be changed multiple times

4. Revenue tracking:
   - revenue field is separate from estimated_value
   - revenue is actual amount after conversion
   - estimated_value is the predicted deal size before conversion

5. Lead vs Vendor relationship:
   - One lead can convert to one vendor
   - Vendor created from lead links back via lead_id
   - Conversion record tracks the relationship
   - Multiple leads can convert to same existing vendor (if email generated matches)

6. Commission calculation:
   - Commission is calculated as: (conversion_value * commission_rate) / 100
   - Should be set only when converting
   - Stored in conversions table for reporting

7. Priority updates:
   - Can be changed at any time
   - Consider adding "priority_changed" event when updated
   - High priority leads should be prominently displayed
