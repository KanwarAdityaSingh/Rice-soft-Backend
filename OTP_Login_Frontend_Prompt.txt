            ================================================================================
OTP LOGIN FRONTEND IMPLEMENTATION GUIDE
================================================================================

This guide provides all technical details needed to implement OTP-based passwordless
login in the frontend. Focus on logic and functionality only - no styling required.

================================================================================
SECTION 1: OTP LOGIN OVERVIEW
================================================================================

Login Flow Options:
1. Password Login (existing) - Username + Password
2. OTP Login (new) - Phone Number + OTP via SMS

OTP Login Flow:
1. User enters phone number → Request OTP
2. OTP sent via SMS to user's phone
3. User enters 6-digit OTP → Verify OTP
4. On success: Receive JWT token (same as password login)
5. Store token and redirect to dashboard

Key Features:
- OTP expires in 30 minutes
- OTP can be attempted 5 times before requiring new OTP
- Resend cooldown: 45 seconds between requests
- Generic success message (prevents user enumeration)
- Same JWT token structure as password login
- Login history tracked for OTP logins

IMPORTANT:
- Phone number format: Accept 10-digit Indian numbers (e.g., 9876543210)
- Backend normalizes to 91XXXXXXXXXX format automatically
- Always show generic "OTP sent" message (even if phone doesn't exist)
- OTP is 6 digits numeric only
- Rate limiting: 5 requests per minute per IP+phone for requestOtp
- Rate limiting: 10 requests per 15 minutes per IP+phone for verifyOtp

SECTION 2: REQUEST OTP ENDPOINT
================================================================================

API ENDPOINT:
POST http://localhost:3000/api/v1/auth/requestOtp

HEADERS:
Content-Type: application/json

REQUEST BODY:
{
  "phone": "9876543210"  // 10-digit Indian phone number (required)
}

SUCCESS RESPONSE (202 Accepted):
{
  "success": true,
  "message": "If the phone exists, an OTP has been sent",
  "data": {
    "sent": true
  },
  "timestamp": "2025-11-11T09:19:14.402Z"
}

ERROR RESPONSE (400 Bad Request):
{
  "success": false,
  "message": "Validation failed",
  "error": "\"phone\" is required",
  "timestamp": "2025-11-11T09:19:14.402Z"
}

ERROR RESPONSE (429 Too Many Requests):
{
  "success": false,
  "message": "Too many requests",
  "error": "Too many OTP requests. Please try again later.",
  "timestamp": "2025-11-11T09:19:14.402Z"
}

FRONTEND LOGIC:

1. VALIDATION:
   - Phone must be exactly 10 digits (Indian format)
   - Strip spaces, dashes, parentheses before validation
   - Show error if phone is not 10 digits
   - Example valid formats: "9876543210", "98765 43210", "(987) 654-3210"
   - Normalize to digits only before sending: "9876543210"

2. STATE MANAGEMENT:
   - Track: phoneNumber (string), isLoading (boolean), error (string | null)
   - Track: canResend (boolean), resendCooldownSeconds (number)
   - Track: otpSent (boolean) - to show OTP input screen

3. API CALL:
   - Show loading state while requesting
   - Disable submit button during request
   - Always show success message: "OTP sent to your phone if the number exists"
   - Don't reveal if phone exists or not (security)

4. RESEND COOLDOWN:
   - After successful request, start 45-second countdown timer
   - Disable "Resend OTP" button during cooldown
   - Show countdown: "Resend in 45s", "Resend in 44s", etc.
   - After cooldown, enable resend button
   - Resend uses same endpoint (requestOtp)

5. ERROR HANDLING:
   - 400: Show validation error (phone format)
   - 429: Show "Too many requests. Please wait X seconds."
   - Network error: Show "Unable to send OTP. Please check your connection."
   - Always allow retry after error

6. SUCCESS FLOW:
   - Show success message
   - Switch to OTP input screen
   - Start 30-minute expiry countdown (optional UI)
   - Start 45-second resend cooldown timer

  "success": false,

}

ERROR RESPONSE (429 Too Many Requests):

  "message": "Too many requests",
  "error": "Too many verification attempts. Please try again later.",
  "timestamp": "2025-11-11T09:19:32.572Z"

FRONTEND LOGIC:

1. VALIDATION:
   - OTP must be exactly 6 digits
   - Only numeric characters allowed
   - Auto-format: Remove non-numeric characters
   - Show error if OTP is not 6 digits
   - Phone must match the one used in requestOtp

2. STATE MANAGEMENT:
   - Track: otp (string), phoneNumber (string), isLoading (boolean)
   - Track: error (string | null), attemptsRemaining (number, default: 5)
   - Track: isExpired (boolean) - for 30-minute expiry
   - Store phoneNumber from requestOtp step

3. OTP INPUT UI:
   - Use 6 separate input fields OR single input with maxLength=6
   - Auto-focus next field when digit entered (if using separate fields)
   - Auto-submit when 6 digits entered (optional)
   - Allow paste of 6-digit code
   - Show character count: "3/6" or similar

4. API CALL:
   - Show loading state during verification
   - Disable submit button during request
   - Decrement attemptsRemaining on error
   - Track attempts to show "X attempts remaining"

5. SUCCESS HANDLING:
   - Store JWT token (same as password login)
   - Store user data in auth context/state
   - Store permissions if needed
   - Clear OTP input fields
   - Redirect to dashboard/home
   - Show success message (optional)

6. ERROR HANDLING:
   - "Invalid OTP": 
     * Clear OTP input
     * Show error: "Invalid OTP. Please try again."
     * Decrement attempts counter
     * Show "X attempts remaining"
   
   - "OTP expired or not found":
     * Show error: "OTP has expired. Please request a new one."
     * Allow user to go back and request new OTP
     * Clear current OTP state
   
   - "Too many invalid attempts":
     * Show error: "Too many failed attempts. Please request a new OTP."
     * Disable OTP input
     * Show "Request New OTP" button
     * Reset attempts counter after new OTP requested
   
   - 429 Rate Limit:
     * Show: "Too many verification attempts. Please wait X seconds."
     * Disable submit button with countdown
   
   - Network error:
     * Show: "Unable to verify OTP. Please check your connection."
     * Allow retry

7. ATTEMPTS TRACKING:
   - Start with 5 attempts remaining
   - Show: "5 attempts remaining", "4 attempts remaining", etc.
   - After 5 failed attempts, require new OTP
   - Reset attempts when new OTP is requested

8. EXPIRY HANDLING:
   - Optional: Show 30-minute countdown timer
   - If expired, show message: "OTP expired. Request a new one."
   - Auto-disable submit if expired (client-side check)
   - Backend will also reject expired OTPs

API SERVICE FUNCTIONS:

// Request OTP
async function requestOtp(phone: string): Promise<RequestOtpResponse> {
  const normalizedPhone = phone.replace(/\D/g, ''); // Remove non-digits
  
  if (normalizedPhone.length !== 10) {
    throw new Error('Phone must be 10 digits');
  }
  
  const response = await api.post<RequestOtpResponse>('/auth/requestOtp', {
    phone: normalizedPhone,
  });
  
  return response.data;
}

// Verify OTP
async function verifyOtp(phone: string, otp: string): Promise<VerifyOtpResponse> {
  const normalizedPhone = phone.replace(/\D/g, '');
  const normalizedOtp = otp.replace(/\D/g, '');
  
  if (normalizedPhone.length !== 10) {
    throw new Error('Phone must be 10 digits');
  }
  
  if (normalizedOtp.length !== 6) {
    throw new Error('OTP must be 6 digits');
  }
  
  const response = await api.post<VerifyOtpResponse>('/auth/verifyOtp', {
    phone: normalizedPhone,
    otp: normalizedOtp,
  });
  
  return response.data;
}

PHONE INPUT COMPONENT:

function PhoneInputStep({ onOtpSent }: { onOtpSent: () => void }) {
  const [phone, setPhone] = useState('');
  const [error, setError] = useState<string | null>(null);
  const [isLoading, setIsLoading] = useState(false);
  
  const handlePhoneChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const value = e.target.value.replace(/\D/g, '').slice(0, 10);
    setPhone(value);
    setError(null);
  };
  
  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    
    if (phone.length !== 10) {
      setError('Please enter a valid 10-digit phone number');
      return;
    }
    
    setIsLoading(true);
    setError(null);
    
    try {
      await requestOtp(phone);
      onOtpSent();
      // Show success message
    } catch (err) {
      // Handle error
      setError('Unable to send OTP. Please try again.');
    } finally {
      setIsLoading(false);
    }
  };
  
  return (
    <form onSubmit={handleSubmit}>
      <input
        type="tel"
        value={phone}
        onChange={handlePhoneChange}
        placeholder="Enter 10-digit phone number"
        maxLength={10}
        disabled={isLoading}
      />
      {error && <div>{error}</div>}
      <button type="submit" disabled={isLoading || phone.length !== 10}>
        {isLoading ? 'Sending...' : 'Send OTP'}
      </button>
    </form>
  );
}

OTP INPUT COMPONENT:

function OTPVerificationStep({ phone }: { phone: string }) {
  const [otp, setOtp] = useState('');
  const [error, setError] = useState<string | null>(null);
  const [isLoading, setIsLoading] = useState(false);
  const [attemptsRemaining, setAttemptsRemaining] = useState(5);
  
  const handleOtpChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const value = e.target.value.replace(/\D/g, '').slice(0, 6);
    setOtp(value);
    setError(null);
  };
  
  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    
    if (otp.length !== 6) {
      setError('Please enter a valid 6-digit OTP');
      return;
    }
    
    setIsLoading(true);
    setError(null);
    
    try {
      const response = await verifyOtp(phone, otp);
      // Store token
      localStorage.setItem('token', response.data.token);
      // Store user data
      // Redirect to dashboard
    } catch (err: any) {
      if (err.response?.status === 401) {
        const errorMsg = err.response.data.error;
        if (errorMsg.includes('expired')) {
          setError('OTP has expired. Please request a new one.');
        } else if (errorMsg.includes('Too many')) {
          setError('Too many failed attempts. Please request a new OTP.');
          setAttemptsRemaining(0);
        } else {
          setAttemptsRemaining(prev => {
            const newAttempts = prev - 1;
            if (newAttempts === 0) {
              setError('Too many failed attempts. Please request a new OTP.');
            } else {
              setError(`Invalid OTP. ${newAttempts} attempts remaining.`);
            }
            return newAttempts;
          });
        }
      } else {
        setError('Unable to verify OTP. Please try again.');
      }
    } finally {
      setIsLoading(false);
    }
  };
  
  return (
    <form onSubmit={handleSubmit}>
      <input
        type="text"
        value={otp}
        onChange={handleOtpChange}
        placeholder="Enter 6-digit OTP"
        maxLength={6}
        disabled={isLoading || attemptsRemaining === 0}
      />
      {error && <div>{error}</div>}
      {attemptsRemaining > 0 && (
        <div>{attemptsRemaining} attempts remaining</div>
      )}
      <button 
        type="submit" 
        disabled={isLoading || otp.length !== 6 || attemptsRemaining === 0}
      >
        {isLoading ? 'Verifying...' : 'Verify OTP'}
      </button>
    </form>
  );
}

SECTION 13: SECURITY CONSIDERATIONS
================================================================================

1. NEVER reveal if phone exists:
   - Always show "OTP sent" message (even if phone doesn't exist)
   - Don't show different messages for existing vs non-existing phones
   - This prevents user enumeration attacks

2. RATE LIMITING:
   - Respect rate limits from backend
   - Show countdown timers for rate limit errors
   - Don't allow rapid-fire requests

3. OTP HANDLING:
   - Never log OTP to console
   - Clear OTP from state after successful login
   - Clear OTP from state on component unmount
   - Don't store OTP in localStorage

4. PHONE NUMBER:
   - Normalize before sending (digits only)
   - Don't store raw phone with formatting
   - Clear phone from state after successful login (optional)

5. ERROR MESSAGES:
   - Don't reveal system internals in errors
   - Use generic error messages
   - Don't expose API structure in errors

PHONE NUMBER FORMATS ACCEPTED:
- "9876543210" (10 digits)

BACKEND NORMALIZATION:
- Backend automatically normalizes phone to 91XXXXXXXXXX format
- Frontend should send 10-digit number, backend handles country code
- Backend handles phone matching (flexible format matching)

TAB SWITCHING:
- User can switch between Password and OTP tabs
- Switching tabs should clear OTP state
- Switching tabs should reset to phone input step
- Don't persist OTP state across tab switches

PERSISTENCE:
- Don't persist OTP or phone in localStorage
- Don't persist OTP state across page refreshes
- User must complete OTP flow in single session
- If page refreshes, user must start over

ACCESSIBILITY:
- Label all inputs properly
- Show error messages clearly
- Disable buttons with clear indication
- Show loading states
- Support keyboard navigation

SECTION 15: API ENDPOINTS SUMMARY
================================================================================

REQUEST OTP:
POST /api/v1/auth/requestOtp
Body: { phone: "9876543210" }
Response: 202 Accepted
Rate Limit: 5 requests/minute per IP+phone

VERIFY OTP:
POST /api/v1/auth/verifyOtp
Body: { phone: "9876543210", otp: "123456" }
Response: 200 OK (with token) or 401 Unauthorized
Rate Limit: 10 requests/15 minutes per IP+phone

Both endpoints are public (no authentication required).
