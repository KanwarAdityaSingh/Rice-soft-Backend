================================================================================
RICE SOFT BACKEND - FRONTEND API INTEGRATION GUIDE
================================================================================

This document contains all technical details needed to integrate with the 
Rice Soft Backend API. Use this as a reference for implementing API calls, 
handling authentication, and managing state in the frontend application.

================================================================================
1. BASE API CONFIGURATION
================================================================================

Base URL: http://localhost:3000/api/v1
Environment Variable Recommended: REACT_APP_API_BASE_URL or NEXT_PUBLIC_API_URL

All endpoints use the /api/v1 prefix.

CORS Configuration:
- Origin: http://localhost:3001 (configurable via .env)
- Credentials: Enabled (supports cookies/auth headers)

Security Headers:
- Helmet.js enabled
- Rate limiting active (see section 8)

================================================================================
2. STANDARD API RESPONSE FORMAT
================================================================================

All API responses follow this structure:

SUCCESS RESPONSE:
{
  "success": true,
  "message": "Optional success message",
  "data": { /* actual response data */ },
  "timestamp": "2025-10-13T04:40:28.280Z"
}

ERROR RESPONSE:
{
  "success": false,
  "message": "Error message",
  "error": "Detailed error information",
  "timestamp": "2025-10-13T04:40:28.280Z"
}

HTTP Status Codes:
- 200: Success
- 201: Resource Created
- 204: No Content (successful delete)
- 400: Bad Request (validation error)
- 401: Unauthorized (missing or invalid token)
- 403: Forbidden (insufficient permissions)
- 404: Not Found
- 409: Conflict (duplicate resource)
- 429: Too Many Requests (rate limit exceeded)
- 500: Internal Server Error

================================================================================
3. AUTHENTICATION & AUTHORIZATION
================================================================================

AUTHENTICATION METHOD: JWT Bearer Token

TOKEN STORAGE:
- Store JWT token securely (localStorage, sessionStorage, or httpOnly cookie)
- Token expires in 24 hours (configurable)
- Include token in all authenticated requests

REQUEST HEADER FORMAT:
Authorization: Bearer <your_jwt_token>

TOKEN PAYLOAD STRUCTURE (decoded):
{
  "userId": "uuid",
  "username": "string",
  "roleId": "uuid",
  "roleName": "admin | salesman | accountant | warehouse_operator | broker | viewer",
  "iat": timestamp,
  "exp": timestamp
}

ROLE-BASED PERMISSIONS:
- admin: Full access to all endpoints
- salesman: Limited to own resources, no user management
- accountant: Read access to most resources
- warehouse_operator: Inventory management
- broker: Contract and negotiation access
- viewer: Read-only access

8. RATE LIMITING
================================================================================

GENERAL RATE LIMIT:
- 100 requests per 15 minutes per IP
- Applies to all endpoints except auth

AUTH RATE LIMIT:
- 5 requests per 15 minutes per IP
- Applies to /auth/login endpoint only

RATE LIMIT HEADERS (included in response):
- X-RateLimit-Limit: Maximum requests allowed
- X-RateLimit-Remaining: Remaining requests
- X-RateLimit-Reset: Time until limit resets (timestamp)

429 RESPONSE (Too Many Requests):
{
  "success": false,
  "message": "Too many requests",
  "error": "Rate limit exceeded. Please try again later.",
  "timestamp": "ISO date string"
}

Frontend Logic:
1. Display rate limit error to user
2. Show countdown timer for retry
3. Implement exponential backoff for retries
4. Monitor rate limit headers to show warnings

================================================================================
9. ERROR HANDLING STRATEGY
================================================================================

IMPLEMENT GLOBAL ERROR HANDLER:

Handle these error types:

1. NETWORK ERRORS (no response from server):
   - Show: "Unable to connect to server. Please check your connection."
   - Action: Retry button, check network status

2. 401 UNAUTHORIZED:
   - Token expired or invalid
   - Action: Clear auth state, redirect to login
   - Show: "Session expired. Please login again."

3. 403 FORBIDDEN:
   - User lacks permission
   - Show: "You don't have permission to perform this action."
   - Action: Disable unavailable features

4. 404 NOT FOUND:
   - Resource doesn't exist
   - Show: "Resource not found."
   - Action: Redirect to list/dashboard

5. 409 CONFLICT:
   - Duplicate resource (username, email, etc.)
   - Show specific field error
   - Action: Highlight conflicting field

6. 400 BAD REQUEST:
   - Validation error
   - Show: Field-specific error messages
   - Action: Highlight invalid fields

7. 429 TOO MANY REQUESTS:
   - Rate limit exceeded
   - Show: "Too many attempts. Please try again in X minutes."
   - Action: Disable submit button with countdown

8. 500 INTERNAL SERVER ERROR:
   - Server error
   - Show: "Something went wrong. Please try again later."
   - Action: Log error, show error ID if available

// Setup axios instance
import axios from 'axios';

const api = axios.create({
  baseURL: process.env.REACT_APP_API_BASE_URL || 'http://localhost:3000/api/v1',
  timeout: 10000,
  headers: {
    'Content-Type': 'application/json',
  },
});

// Add token to all requests
api.interceptors.request.use(
  (config) => {
    const token = localStorage.getItem('token');
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// Handle 401 globally
api.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      localStorage.removeItem('token');
      window.location.href = '/login';
    }
    return Promise.reject(error);
  }
);

// Login
async function login(username: string, password: string) {
  const response = await api.post<ApiResponse<LoginResponse>>('/auth/login', {
    username,
    password,
  });
  
  if (response.data.success && response.data.data) {
    const { token, user } = response.data.data;
    localStorage.setItem('token', token);
    return { token, user };
  }
  
  throw new Error(response.data.error || 'Login failed');
}

// Get all users
async function getUsers(includeInactive = false) {
  const response = await api.get<ApiResponse<User[]>>('/users', {
    params: { include_inactive: includeInactive },
  });
  return response.data.data;
}

// Create user
async function createUser(userData: CreateUserRequest) {
  const response = await api.post<ApiResponse<User>>('/users', userData);
  return response.data.data;
}

// Update user
async function updateUser(userId: string, userData: UpdateUserRequest) {
  const response = await api.put<ApiResponse<User>>(`/users/${userId}`, userData);
  return response.data.data;
}

// Delete user
async function deleteUser(userId: string) {
  await api.delete(`/users/${userId}`);
}

// Get all roles
async function getRoles() {
  const response = await api.get<ApiResponse<Role[]>>('/roles');
  return response.data.data;
}

// Error handling example
try {
  const users = await getUsers();
  // Handle success
} catch (error) {
  if (axios.isAxiosError(error)) {
    const apiError = error.response?.data as ApiResponse;
    // Show error to user: apiError.error || apiError.message
  } else {
    // Network error or other error
    // Show generic error message
  }
}

13. SECURITY BEST PRACTICES
================================================================================

1. TOKEN STORAGE:
   - Use httpOnly cookies (most secure) OR
   - Use sessionStorage (cleared on tab close) OR
   - Use localStorage (persists across sessions)
   - NEVER store in plain text or expose to XSS

2. TOKEN TRANSMISSION:
   - Always use HTTPS in production
   - Never send token in URL parameters
   - Use Authorization header

3. SENSITIVE DATA:
   - Never log tokens or passwords to console
   - Clear sensitive data on logout
   - Don't cache sensitive information

4. PERMISSIONS:
   - Check permissions on frontend (UX)
   - Always rely on backend for actual authorization
   - Hide UI elements user can't access
   - Handle 403 errors gracefully

5. INPUT VALIDATION:
   - Validate all inputs client-side
   - Sanitize user inputs
   - Use parameterized queries (backend does this)
   - Prevent XSS attacks

6. RATE LIMITING:
   - Respect rate limits
   - Don't retry too aggressively
   - Implement exponential backoff
