1. CREATE BROKER (Standard)
================================================================================

Endpoint: POST /api/v1/brokers/createBroker
Method: POST
Authentication: Required
Content-Type: application/json

REQUEST BODY:
{
  "business_name": string (optional, 2-255 chars, can be null or empty),
  "contact_persons": array (REQUIRED, minimum 1 item) [
    {
      "name": string (REQUIRED, 2-255 chars),
      "phones": array (REQUIRED, minimum 1 phone) [
        string (max 20 chars)
      ],
      "emails": array (optional) [
        string (valid email format, can be empty string or null)
      ]
    }
  ],
  "address": object (REQUIRED) {
    "street": string (REQUIRED, max 255 chars),
    "city": string (REQUIRED, max 100 chars),
    "state": string (REQUIRED, max 100 chars),
    "pincode": string (optional, can be empty, max 10 chars),
    "country": string (REQUIRED, max 100 chars)
  },
  "business_details": object (REQUIRED) {
    "pan_number": string (optional, exactly 10 chars, uppercase, can be null/empty),
    "aadhaar_number": string (optional, 12 digits, cannot start with 0 or 1, can be null/empty),
    "gst_number": string (optional, exactly 15 chars, uppercase, can be null/empty),
    "business_type": string (REQUIRED) - must be one of: "individual", "partnership", "company", "llp"
  },
  "bank_details": object (optional) {
    "account_holder_name": string (optional, max 255 chars, can be null/empty),
    "account_number": string (optional, max 50 chars, can be null/empty),
    "ifsc_code": string (optional, exactly 11 chars, can be null/empty),
    "bank_name": string (optional, max 255 chars, can be null/empty),
    "branch": string (optional, max 255 chars, can be null/empty)
  },
  "broker_details": object (optional) {
    "commission_rate": number (optional, 0-100),
    "specialization": string (optional, max 255 chars, can be null/empty),
    "experience_years": string (optional, max 100 chars, can be null/empty)
  },
  "type": string (REQUIRED) - must be one of: "purchase", "sale", "both",
  "is_active": boolean (optional, defaults to true)
}

IMPORTANT VALIDATION RULES:
- For business_type "individual": Either PAN number OR Aadhaar number MUST be provided
- For business_type "company", "partnership", or "llp": GST number MUST be provided
- At least one contact person with at least one phone number is REQUIRED
- If email is provided in contact_persons[0].emails[0], it must be unique across all brokers and users
- PAN, Aadhaar, and GST numbers must be unique if provided
- PAN number will be automatically converted to uppercase
- Aadhaar number spaces will be automatically removed

SUCCESS RESPONSE (201 Created):
{
  "success": true,
  "message": "Broker created successfully",
  "data": {
    "id": "uuid",
    "business_name": "string or null",
    "contact_persons": [
      {
        "name": "string",
        "phones": ["string"],
        "emails": ["string"] (optional)
      }
    ],
    "address": {
      "street": "string",
      "city": "string",
      "state": "string",
      "pincode": "string",
      "country": "string"
    },
    "business_details": {
      "pan_number": "string or null",
      "aadhaar_number": "string or null",
      "gst_number": "string or null",
      "business_type": "string"
    },
    "bank_details": {
      "account_holder_name": "string or null",
      "account_number": "string or null",
      "ifsc_code": "string or null",
      "bank_name": "string or null",
      "branch": "string or null"
    } or null,
    "broker_details": {
      "commission_rate": "number or null",
      "specialization": "string or null",
      "experience_years": "string or null"
    } or null,
    "type": "purchase" | "sale" | "both",
    "is_active": boolean,
    "created_at": "ISO 8601 timestamp string",
    "updated_at": "ISO 8601 timestamp string"
  },
  "timestamp": "ISO 8601 timestamp string",

ERROR RESPONSES:

2. UPDATE BROKER
================================================================================

Endpoint: POST /api/v1/brokers/updateBroker/:id
Method: POST
Authentication: Required
Content-Type: application/json

URL PARAMETERS:
- id: string (REQUIRED) - UUID of the broker to update

REQUEST BODY:
All fields are OPTIONAL, but at least one field must be provided:
{
  "business_name": string (optional, 2-255 chars, can be null or empty),
  "contact_persons": array (optional, minimum 1 item if provided) [
    {
      "name": string (REQUIRED if contact_persons provided, 2-255 chars),
      "phones": array (REQUIRED if contact_persons provided, minimum 1 phone) [
        string (max 20 chars)
      ],
      "emails": array (optional) [
        string (valid email format, can be empty string or null)
      ]
    }
  ],
  "address": object (optional) {
    "street": string (REQUIRED if address provided, max 255 chars),
    "city": string (REQUIRED if address provided, max 100 chars),
    "state": string (REQUIRED if address provided, max 100 chars),
    "pincode": string (optional, can be empty, max 10 chars),
    "country": string (REQUIRED if address provided, max 100 chars)
  },
  "business_details": object (optional) {
    "pan_number": string (optional, exactly 10 chars, uppercase, can be null/empty),
    "aadhaar_number": string (optional, 12 digits, cannot start with 0 or 1, can be null/empty),
    "gst_number": string (optional, exactly 15 chars, uppercase, can be null/empty),
    "business_type": string (optional) - must be one of: "individual", "partnership", "company", "llp"
  },
  "bank_details": object (optional) {
    "account_holder_name": string (optional, max 255 chars, can be null/empty),
    "account_number": string (optional, max 50 chars, can be null/empty),
    "ifsc_code": string (optional, exactly 11 chars, can be null/empty),
    "bank_name": string (optional, max 255 chars, can be null/empty),
    "branch": string (optional, max 255 chars, can be null/empty)
  },
  "broker_details": object (optional) {
    "commission_rate": number (optional, 0-100),
    "specialization": string (optional, max 255 chars, can be null/empty),
    "experience_years": string (optional, max 100 chars, can be null/empty)
  },
  "type": string (optional) - must be one of: "purchase", "sale", "both",
  "is_active": boolean (optional)
}

IMPORTANT NOTES:
- At least one field must be provided in the request body
- If updating contact_persons, all validation rules apply (name required, phones required, etc.)
- If updating business_details, validation rules still apply:
  * For "individual": Either PAN or Aadhaar must be present
  * For "company"/"partnership"/"llp": GST must be present
- Email, PAN, Aadhaar, and GST uniqueness checks are performed if those fields are being updated
- The broker ID in the URL must be a valid UUID

SUCCESS RESPONSE (200 OK):
{
  "success": true,
  "message": "Broker updated successfully",
  "data": {
    // Same structure as create response
  },
  "timestamp": "ISO 8601 timestamp string",
  "isSessionValid": true
}

ERROR RESPONSES:

400 Bad Request - Validation Error:
Same as create endpoint

404 Not Found:
{
  "success": false,
  "message": "Resource not found",
  "error": "Broker not found",
  "timestamp": "ISO 8601 timestamp string",
  "isSessionValid": true
}

Same as create endpoint

Same as create endpoint

================================================================================
COMMON ERROR HANDLING
================================================================================

All endpoints follow a consistent error response format:

{
  "success": false,
  "message": "Error message",
  "error": "Detailed error description",
  "timestamp": "ISO 8601 timestamp string",
  "isSessionValid": true | false
}

HTTP STATUS CODES:
- 200 OK: Successful GET/POST request
- 201 Created: Successful resource creation
- 400 Bad Request: Validation errors, invalid input
- 401 Unauthorized: Missing or invalid authentication token
- 404 Not Found: Resource not found
- 409 Conflict: Duplicate data, constraint violations
- 500 Internal Server Error: Server errors, database errors, external API failures

ERROR HANDLING BEST PRACTICES:
1. Always check the "success" field first
2. If success is false, check the "error" field for details
3. Handle 400 errors by showing validation messages to the user
4. Handle 409 errors by informing the user about duplicate data
5. Handle 404 errors by showing "not found" messages
6. Handle 500 errors by showing a generic error message and asking user to retry
7. Check "isSessionValid" to determine if user needs to re-authenticate

}

BankDetails:
{
  account_holder_name?: string (max 255 chars)
