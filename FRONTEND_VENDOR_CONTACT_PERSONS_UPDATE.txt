================================================================================
FRONTEND UPDATE GUIDE: Vendor & Broker Contact Persons Change
================================================================================

SUMMARY:
--------
Both Vendor and Broker APIs have been updated to use `contact_persons` array 
as the primary source for contact information. The separate `email` and `phone` 
fields have been removed from the API request/response.

This change affects:
- Vendor: Create, Edit, Detail, List views, Create from GST/PAN flows
- Broker: Create, Edit, Detail, List views, Create from PAN flow

================================================================================
VENDOR CHANGES
================================================================================

OLD VENDOR STRUCTURE (DEPRECATED):
----------------------------------
interface CreateVendorDTO {
  business_name: string;
  contact_person: string;      // REMOVED
  email?: string;               // REMOVED
  phone: string;                // REMOVED
  address: Address;
  business_details: BusinessDetails;
  bank_details?: BankDetails;
  type: 'purchaser' | 'seller' | 'both';
  is_active?: boolean;
}

NEW VENDOR STRUCTURE:
---------------------
interface ContactPerson {
  name: string;
  phones: string[];     // Array of phone numbers (at least one required)
  emails?: string[];    // Optional array of email addresses
}

interface CreateVendorDTO {
  business_name: string;
  contact_persons: ContactPerson[];  // NEW - Array of contact persons
  address: Address;
  business_details: BusinessDetails;
  bank_details?: BankDetails;
  type: 'purchaser' | 'seller' | 'both';
  is_active?: boolean;
}

interface VendorResponse {
  id: string;
  business_name: string;
  contact_persons: ContactPerson[];  // NEW - Array instead of single fields
  address: Address;
  business_details: BusinessDetails;
  bank_details: BankDetails | null;
  type: 'purchaser' | 'seller' | 'both';
  is_active: boolean;
  user_id: string | null;
  lead_id: string | null;
  created_at: string;
  updated_at: string;
  last_enquiry_date: string | null;
  google_location_link: string | null;
  business_card_url: string | null;
}

FORM UPDATE INSTRUCTIONS (BOTH VENDOR & BROKER):
================================================================================

1. CREATE / EDIT FORMS
----------------------
Replace:
- Single "Contact Person" text input (for vendor)
- Single "Email" text input  
- Single "Phone" text input

With:
- Dynamic contact persons section
- Each contact person has:
  - Name (required)
  - Phones array (at least 1 required, can add more)
  - Emails array (optional, can add multiple)
- "Add Contact Person" button to add more contact persons

Example form structure:
```
Contact Persons:
┌────────────────────────────────────────────────────────┐
│ Contact Person 1                               [Remove]│
│ ┌──────────────────────────────────────────────────┐  │
│ │ Name: [_________________________]                │  │
│ └──────────────────────────────────────────────────┘  │
│ Phones:                                               │
│ ┌───────────────────────────────┐ [+]                │
│ │ [_____________________] [×]   │                    │
│ └───────────────────────────────┘                    │
│ Emails (optional):                                    │
│ ┌───────────────────────────────┐ [+]                │
│ │ [_____________________] [×]   │                    │
│ └───────────────────────────────┘                    │
└────────────────────────────────────────────────────────┘

[+ Add Contact Person]
```

2. DETAIL VIEW
--------------
Display all contact persons in a list or card format:

Example:
```
Contact Persons:
┌─────────────────────────────────────────────┐
│ Rajesh Kumar                                │
│ 📞 +91 9876543210, +91 9876543211          │
│ ✉️ rajesh@company.com                       │
```

3. LIST VIEW
------------
For the list/table view, you can show the first contact person's info:
- Primary Contact: contact_persons[0].name
- Primary Phone: contact_persons[0].phones[0]
- Primary Email: contact_persons[0].emails?.[0] || '-'

================================================================================
VALIDATION RULES:
================================================================================

For both Vendors and Brokers:

1. contact_persons: Required, at least 1 contact person
2. Each contact person:
   - name: Required, min 2 chars, max 255 chars
   - phones: Required, at least 1 phone number, each max 20 chars
   - emails: Optional, if provided each must be valid email format

================================================================================
USER CREATION LOGIC:
================================================================================

For both Vendors and Brokers:

When an entity is created and the first contact person has an email:
- A user account is automatically created
- Username is generated from the first contact person's name
- Email is taken from: contact_persons[0].emails[0]
- Phone is taken from: contact_persons[0].phones[0]
- The user is linked to the entity via user_id

If no email is provided in contact_persons[0].emails, no user is created.

================================================================================
MIGRATION NOTES:
================================================================================

1. Existing vendors in the database have been migrated automatically
2. Their old contact_person, email, phone are now in contact_persons[0]
3. Existing brokers already had contact_persons but also had separate email/phone
4. The old fields still exist in the database for backward compatibility
5. API responses now only return contact_persons (not the old email/phone fields)

NEW FEATURE: IFSC LOOKUP API (Bank Details Auto-Fill)
================================================================================

A new API has been added to lookup bank details by IFSC code. This can be used
in Vendor and Broker forms to auto-fill bank name and branch when user enters
an IFSC code.

API ENDPOINTS:
--------------

1. IFSC LOOKUP (Get bank details by IFSC code)
   GET /api/v1/bank/lookupIFSC?ifsc=HDFC0001234

   Response:
   {
     "success": true,
     "data": {
       "ifsc_details": {
         "ifsc_code": "HDFC0001234",
         "bank_name": "HDFC Bank",
         "branch": "Mumbai Main Branch",
         "address": "123 Main Street, Mumbai",
         "city": "Mumbai",
         "district": "Mumbai",
         "state": "Maharashtra",
         "contact": "+912212345678",
         "micr_code": "400240001",
         "swift_code": "HDFCINBB",
         "supports": {
           "imps": true,
           "rtgs": true,
           "neft": true,
           "upi": true
         }
       },
       "bank_details": {
         "bank_name": "HDFC Bank",
         "branch": "Mumbai Main Branch",
         "ifsc_code": "HDFC0001234"
       }
     },
     "message": "IFSC lookup successful"
   }

2. IFSC FORMAT VALIDATION (Validate format without lookup)
   GET /api/v1/bank/validateIFSC?ifsc=HDFC0001234

   Response:
   {
     "success": true,
     "data": {
       "ifsc_code": "HDFC0001234",
       "is_valid": true,
       "message": "IFSC code format is valid"
     },
     "message": "IFSC validation completed"
   }

IFSC CODE FORMAT:
-----------------
- Total 11 characters
- First 4 characters: Bank code (letters only, e.g., HDFC, ICIC, SBIN)
- 5th character: Always 0 (zero)
- Last 6 characters: Branch code (alphanumeric)
- Example: HDFC0001234

IMPLEMENTATION IN FORMS:
------------------------

1. Add an IFSC input field in the Bank Details section
2. When user enters 11 characters in IFSC field:
   - Validate format client-side first
   - Call /api/v1/bank/lookupIFSC?ifsc=<entered_value>
   - On success, auto-fill:
     - Bank Name: response.data.bank_details.bank_name
     - Branch: response.data.bank_details.branch
   - On error (404), show message: "IFSC code not found"
3. Allow user to manually edit auto-filled values if needed

EXAMPLE FORM FLOW:
------------------

```
Bank Details:
┌─────────────────────────────────────────────────────────┐
│ IFSC Code: [HDFC0001234_____] [🔍 Lookup]              │
│                                                         │
│ Bank Name: [HDFC Bank___________] (auto-filled)        │
│ Branch:    [Mumbai Main Branch__] (auto-filled)        │
│                                                         │
│ Account Holder Name: [Rajesh Kumar______]              │
│ Account Number:      [12345678901234____]              │
└─────────────────────────────────────────────────────────┘
```

DEBOUNCE RECOMMENDATION:
------------------------
- Use debounce (300-500ms) on IFSC input to avoid too many API calls
- Only trigger lookup when exactly 11 characters are entered
- Show loading indicator while fetching

ERROR HANDLING:
---------------
- Invalid format: "Invalid IFSC code format. Expected: 4 letters + 0 + 6 alphanumeric"
- Not found: "IFSC code not found. Please verify the code."
- API error: "Failed to lookup IFSC details. Please try again."

NEW FEATURE: BROKER BUSINESS TYPE & GST SUPPORT
================================================================================

Brokers now support two registration types with different requirements:

1. INDIVIDUAL BROKERS - Require PAN or Aadhaar
2. COMPANY/PARTNERSHIP/LLP BROKERS - Require GST number

UPDATED BROKER BUSINESS DETAILS:
--------------------------------

interface BusinessDetails {
  pan_number?: string;         // Required for individual
  aadhaar_number?: string;     // Alternative for individual
  gst_number?: string;         // Required for company/partnership/llp
  business_type: 'individual' | 'partnership' | 'company' | 'llp';  // REQUIRED
}

VALIDATION RULES:
-----------------

| Business Type | Required Fields | Optional Fields |
|---------------|-----------------|-----------------|
| individual    | PAN OR Aadhaar  | GST             |
| company       | GST             | PAN, Aadhaar    |
| partnership   | GST             | PAN, Aadhaar    |
| llp           | GST             | PAN, Aadhaar    |

FORM IMPLEMENTATION:
--------------------

1. Add a "Business Type" selector at the top of the form:

```
Business Type: [dropdown]
  - Individual (Person)
  - Company (Pvt Ltd / Ltd)
  - Partnership Firm
  - LLP (Limited Liability Partnership)
```

2. Show/hide fields based on selection:

   IF business_type == 'individual':
     - Show: PAN Number field
     - Show: Aadhaar Number field
     - Hide or Optional: GST Number field
     - Use: /api/v1/brokers/quickCreateFromPAN for quick create

   IF business_type == 'company' OR 'partnership' OR 'llp':
     - Show: GST Number field (with lookup button)
     - Optional: PAN Number (auto-filled from GST)
     - Hide: Aadhaar Number field
     - Use: /api/v1/brokers/quickCreateFromGST for quick create

GST LOOKUP FOR BROKERS:
-----------------------

When user enters GST for company/partnership/llp broker:

1. Call existing GST lookup API:
   GET /api/v1/brokers/lookupGST?gst_number=27ABCDE1234F1Z5

2. Auto-fill from response:
   - Business Name: response.data.mapped_data.business_name
   - Address: response.data.mapped_data.address (street, city, state, pincode)
   - PAN Number: Extracted from GST (characters 3-12)
   - Business Type: Determined from GST entity type
