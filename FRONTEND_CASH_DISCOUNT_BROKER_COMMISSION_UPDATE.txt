================================================================================
FRONTEND UPDATE GUIDE: Cash Discount & Broker Commission Type Support
================================================================================

OVERVIEW
--------
The backend now supports flexible types for both cash_discount and broker_commission:

Cash Discount Types:
1. "rupees" - Fixed amount in rupees
2. "percentage" - Percentage of the base amount

Broker Commission Types:
1. "rupees" - Fixed amount in rupees
2. "percentage" - Percentage of the calculated amount
3. "weight" - Commission per unit weight (NEW!)

Two new fields have been added:
- cash_discount_type: 'rupees' | 'percentage' (default: 'rupees')
- broker_commission_type: 'rupees' | 'percentage' | 'weight' (default: 'percentage')

================================================================================
FRONTEND CHANGES REQUIRED
================================================================================

1. TYPE/INTERFACE UPDATES
-------------------------
   Add these types to your TypeScript interfaces:

   type CashDiscountType = 'rupees' | 'percentage';
   type BrokerCommissionType = 'rupees' | 'percentage' | 'weight';

   Update Sauda interface:
   - Add: cash_discount_type: CashDiscountType;
   - Add: broker_commission_type: BrokerCommissionType;

   Update Purchase interface:
   - Add: cash_discount_type: CashDiscountType;
   - Add: broker_commission_type: BrokerCommissionType;

2. FORM UPDATES
---------------
   Wherever you have input fields for:
   
   a) Cash Discount:
      - Add a dropdown/toggle next to the cash_discount input
      - Options: "₹ (Rupees)" and "% (Percentage)"
      - Default selection: "₹ (Rupees)"
      - When user selects "Rupees", send cash_discount_type: "rupees"
      - When user selects "Percentage", send cash_discount_type: "percentage"

   b) Broker Commission:
      - Add a dropdown/toggle next to the broker_commission input
      - Options: "₹ (Rupees)", "% (Percentage)", and "Per Kg (Weight)"
      - Default selection: "% (Percentage)"
      - When user selects "Rupees", send broker_commission_type: "rupees"
      - When user selects "Percentage", send broker_commission_type: "percentage"
      - When user selects "Per Kg (Weight)", send broker_commission_type: "weight"

3. DISPLAY UPDATES
------------------
   When displaying cash_discount or broker_commission values:

   a) For Cash Discount:
      - If cash_discount_type === 'rupees': Show "₹{value}"
      - If cash_discount_type === 'percentage': Show "{value}%"

   b) For Broker Commission:
      - If broker_commission_type === 'rupees': Show "₹{value}"
      - If broker_commission_type === 'percentage': Show "{value}%"
      - If broker_commission_type === 'weight': Show "₹{value}/Kg"

4. FORMS TO UPDATE

   - Purchase Edit Form

5. DISPLAY COMPONENTS TO UPDATE
-------------------------------
   - Sauda List/Table (if showing these fields)

   - Any summary/calculation display components

================================================================================
CALCULATION LOGIC (For Reference)
================================================================================

The backend calculates amounts as follows:

1. Base Amount = Sum of all lot amounts
   Total Weight = Sum of all lot received weights

2. Cash Discount Calculation:
   - If type = "rupees": discount = cash_discount value (fixed)
   - If type = "percentage": discount = base_amount × (cash_discount / 100)

3. Amount After Discount = Base Amount - Cash Discount

4. Broker Commission Calculation:
   - If type = "rupees": commission = broker_commission value (fixed)
   - If type = "percentage": commission = amount_after_discount × (broker_commission / 100)
   - If type = "weight": commission = broker_commission × total_weight (NEW!)

5. Amount With Commission = Amount After Discount + Broker Commission

6. Then transportation cost and IGST are applied...

Scenario 1: Percentage-based discount and commission

================================================================================
VALIDATION NOTES
================================================================================

- cash_discount: number, min 0, optional
- cash_discount_type: 'rupees' | 'percentage', optional (default: 'rupees')
- broker_commission: number, min 0, optional
- broker_commission_type: 'rupees' | 'percentage' | 'weight', optional (default: 'percentage')

Note: The max(100) validation has been removed from broker_commission to allow 
larger fixed amounts when broker_commission_type is 'rupees' or 'weight'.

================================================================================
BACKWARD COMPATIBILITY
================================================================================

- Existing saudas/purchases will have:
  - cash_discount_type defaulted to 'rupees'
  - broker_commission_type defaulted to 'percentage'
  
- If you don't send these new fields in requests, the defaults will be used.
- The API is backward compatible - old requests without the type fields will 
  continue to work.

================================================================================
WEIGHT-BASED COMMISSION USE CASE
================================================================================

The "weight" option is useful when the broker charges a fixed rate per unit 
weight (e.g., ₹10 per kg, ₹15 per quintal).

Example use case:
- A broker charges ₹12 per kg for their services
- The purchase has a total weight of 5000 kg
- Broker commission = ₹12 × 5000 = ₹60,000

This is different from:
- "rupees" which is a flat fixed amount regardless of weight
- "percentage" which is a percentage of the transaction amount

The weight-based calculation uses the total_weight (sum of received_weight 
from all linked lots) in the formula:
  broker_commission_amount = broker_commission × total_weight
