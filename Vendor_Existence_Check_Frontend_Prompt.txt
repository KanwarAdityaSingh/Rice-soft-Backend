================================================================================
VENDOR EXISTENCE CHECK API - FRONTEND IMPLEMENTATION PROMPT
================================================================================

IMPLEMENTATION TASK:
Create a function/service to check if a vendor exists by GST or PAN number before creating a new vendor/lead. This prevents duplicate vendor creation.

================================================================================
API ENDPOINT DETAILS
================================================================================

ENDPOINT:
GET /api/v1/vendors/checkExists

AUTHENTICATION:
Required - Include Bearer token in Authorization header

QUERY PARAMETERS:
- gst_number (optional): string (15 characters, format: 27ABCDE1234F1Z5)
- pan_number (optional): string (10 characters, format: ABCDE1234F)
- At least one parameter is required

REQUEST EXAMPLE:
GET /api/v1/vendors/checkExists?gst_number=27ABCDE1234F1Z5
GET /api/v1/vendors/checkExists?pan_number=ABCDE1234F
GET /api/v1/vendors/checkExists?gst_number=27ABCDE1234F1Z5&pan_number=ABCDE1234F

1. CREATE API SERVICE FUNCTION:
   - Function name: checkVendorExists
   - Parameters: { gstNumber?: string, panNumber?: string }
   - Returns: Promise with response containing { exists: boolean, vendor: VendorResponse | null }
   - Handle errors appropriately

2. INTEGRATION WITH VENDOR/LEAD CREATION FLOW:
   - Before creating a new vendor/lead, call checkVendorExists
   - If vendor exists (exists: true):
     * Show message to user: "Vendor already exists with this GST/PAN"
     * Display existing vendor details
     * Optionally allow user to use existing vendor or cancel creation
   - If vendor does not exist (exists: false):
     * Proceed with vendor/lead creation flow

3. VALIDATION:
   - Validate GST format: 15 characters, alphanumeric
   - Validate PAN format: 10 characters, alphanumeric
   - Ensure at least one parameter (GST or PAN) is provided before API call

4. ERROR HANDLING:
   - Handle network errors
   - Handle validation errors (show user-friendly messages)
   - Handle authentication errors (redirect to login if needed)

5. LOADING STATES:
   - Show loading indicator while checking vendor existence
   - Disable form submission during check

================================================================================
USAGE SCENARIOS
================================================================================

SCENARIO 1: Check by GST before creating lead
- User enters GST number in lead creation form
- On blur/change, call checkVendorExists with GST
- If vendor exists, show existing vendor details and prevent duplicate lead
- If vendor doesn't exist, allow lead creation

SCENARIO 2: Check by PAN before creating vendor
- User enters PAN number in vendor creation form
- Before form submission, call checkVendorExists with PAN
- If vendor exists, show error message and existing vendor info
- If vendor doesn't exist, proceed with vendor creation

SCENARIO 3: Check by both GST and PAN
- User has both GST and PAN numbers
- Call checkVendorExists with both parameters
- API checks GST first, then PAN if GST not found
- Return result based on which identifier matches

================================================================================
NOTES
================================================================================

- This endpoint is designed to prevent duplicate vendor creation
- Always check vendor existence before creating new vendors/leads
- The endpoint validates GST/PAN format before checking database
- If both GST and PAN are provided, GST is checked first
- Response includes full vendor details if found, useful for pre-filling forms
- Use this check in both vendor creation and lead creation flows
