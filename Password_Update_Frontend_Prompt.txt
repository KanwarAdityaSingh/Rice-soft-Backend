================================================================================
PASSWORD UPDATE FRONTEND IMPLEMENTATION GUIDE
================================================================================

This guide provides all technical details needed to implement password update
functionality in the frontend. Focus on logic and functionality only - no styling required.

================================================================================
SECTION 1: PASSWORD UPDATE OVERVIEW
================================================================================

Password Update Flow:
1. User must be authenticated (logged in)
2. User enters current password
3. User enters new password
4. User confirms new password (frontend validation)
5. Submit → Verify current password
6. On success: Password updated, show success message

Key Features:
- Requires authentication (JWT token in header)
- Validates current password before allowing change
- New password must be different from current password
- Password length: 6-100 characters
- Works for all user types (admin, vendor, broker, salesman, custom)
- No user type restrictions

IMPORTANT:
- Must include JWT token in Authorization header
- Current password verification happens on backend
- New password must be different from current password
- Password confirmation is frontend-only (not sent to backend)


================================================================================
SECTION 2: CHANGE PASSWORD ENDPOINT
================================================================================

API ENDPOINT:
POST http://localhost:3000/api/v1/auth/changeUserPassword

HEADERS:
Content-Type: application/json
Authorization: Bearer <JWT_TOKEN>

REQUEST BODY:
{
  "old_password": "current_password",  // Current password (required)
  "new_password": "new_password"       // New password (required, 6-100 chars)
}

SUCCESS RESPONSE (200 OK):
{
  "success": true,
  "message": "Password changed successfully",
  "data": null,
  "timestamp": "2025-11-11T09:19:14.402Z"
}

ERROR RESPONSE (401 Unauthorized - Wrong Current Password):
{
  "success": false,
  "message": "Current password is incorrect",
  "error": "Current password is incorrect",
  "timestamp": "2025-11-11T09:19:14.402Z"
}

ERROR RESPONSE (400 Bad Request - Same Password):
{
  "success": false,
  "message": "New password must be different from current password",
  "error": "New password must be different from current password",
  "timestamp": "2025-11-11T09:19:14.402Z"
}

ERROR RESPONSE (400 Bad Request - Validation Error):
{
  "success": false,
  "message": "Validation failed",
  "error": "\"new_password\" length must be at least 6 characters long",
  "timestamp": "2025-11-11T09:19:14.402Z"
}

ERROR RESPONSE (401 Unauthorized - No Token):
{
  "success": false,
  "message": "Authentication required",
  "error": "No token provided",
  "timestamp": "2025-11-11T09:19:14.402Z"
}

ERROR RESPONSE (401 Unauthorized - Invalid/Expired Token):
{
  "success": false,
  "message": "Authentication required",
  "error": "Invalid or expired token",
  "timestamp": "2025-11-11T09:19:14.402Z"
}

SECTION 3: FRONTEND IMPLEMENTATION LOGIC
================================================================================

1. VALIDATION:

   a) Current Password:
      - Required field
      - No length restrictions (backend handles)
      - Show error if empty on submit

   b) New Password:
      - Required field
      - Minimum 6 characters
      - Maximum 100 characters
      - Show character count indicator (optional)
      - Validate on blur or submit

   c) Confirm New Password:
      - Required field
      - Must match new password exactly
      - Show error if passwords don't match
      - Validate on blur or submit
      - This is frontend-only validation (not sent to backend)

   d) Password Comparison:
      - New password must be different from current password
      - Show error if new password matches current password
      - This check can be done on frontend before API call
      - Backend also validates this (redundant check for UX)

2. STATE MANAGEMENT:

   Required State:
   - currentPassword: string
   - newPassword: string
   - confirmPassword: string
   - isLoading: boolean
   - error: string | null
   - success: boolean

   Optional State:
   - showCurrentPassword: boolean (for password visibility toggle)
   - showNewPassword: boolean (for password visibility toggle)
   - showConfirmPassword: boolean (for password visibility toggle)
   - passwordStrength: string (weak/medium/strong - optional)

3. FORM SUBMISSION FLOW:

   a) Pre-submit Validation:
      - Check all fields are filled
      - Check new password length (6-100 chars)
      - Check new password matches confirm password
      - Check new password is different from current password
      - If any validation fails, show error and prevent submission

   b) API Call:
      - Get JWT token from storage (localStorage/sessionStorage)
      - Include token in Authorization header: "Bearer <token>"
      - Set isLoading = true
      - Disable submit button
      - Clear previous errors

   c) Success Handling:
      - Set isLoading = false
      - Set success = true
      - Show success message: "Password changed successfully"
      - Clear form fields (optional - can keep them)
      - Redirect to profile/settings page after 2-3 seconds (optional)
      - Or show success message and allow user to close manually

   d) Error Handling:
      - Set isLoading = false
      - Enable submit button
      - Map error responses:
        * "Current password is incorrect" → Show on current password field
        * "New password must be different from current password" → Show on new password field
        * Validation errors → Show specific field error
        * "Authentication required" → Redirect to login page
        * "Invalid or expired token" → Redirect to login page
        * Network errors → Show generic error message

4. SECURITY CONSIDERATIONS:

   - Never store passwords in state longer than necessary
   - Clear password fields after successful submission
   - Clear password fields if user navigates away
   - Don't log password values in console
   - Use secure password input fields (type="password")
   - Optionally implement password visibility toggle
   - Optionally show password strength indicator

5. USER EXPERIENCE:

   - Show loading spinner/state during API call
   - Disable form fields during submission
   - Show clear error messages for each field
   - Highlight fields with errors
   - Show success message prominently
   - Optionally auto-redirect after success
   - Allow user to retry after error
   - Clear errors when user starts typing

6. INTEGRATION POINTS:

   - Get JWT token from authentication context/store
   - Handle token expiration (redirect to login)
   - Update user session if needed after password change
   - Log password change event (if audit logging in frontend)

7. ERROR MESSAGES MAPPING:

   Backend Error → Frontend Display:
   - "Current password is incorrect" → "The current password you entered is incorrect"
   - "New password must be different from current password" → "New password must be different from your current password"
   - "Validation failed" → Parse and show specific validation message
   - "Authentication required" → "Please log in again" (redirect to login)
   - "Invalid or expired token" → "Your session has expired. Please log in again" (redirect to login)
   - Network error → "Unable to update password. Please check your connection and try again."

SECTION 4: EXAMPLE IMPLEMENTATION STRUCTURE
================================================================================

Component Structure:
- PasswordUpdateForm component
  - Form fields: currentPassword, newPassword, confirmPassword
  - Validation logic
  - API integration
  - Error handling
  - Success handling

API Service Function:
- changePassword(oldPassword: string, newPassword: string)
  - Get token from storage
  - Make POST request to /api/v1/auth/changeUserPassword
  - Handle response/errors
  - Return success/error

Validation Functions:
- validateCurrentPassword(password: string): boolean
- validateNewPassword(password: string): { valid: boolean, error?: string }
- validateConfirmPassword(newPassword: string, confirmPassword: string): boolean
- validatePasswordDifferent(currentPassword: string, newPassword: string): boolean

State Management:
- Use React state / Vue state / Angular reactive forms
- Manage form state, loading state, error state
- Handle form submission


================================================================================
SECTION 5: TESTING SCENARIOS
================================================================================

Test Cases to Cover:

1. Happy Path:
   - Valid current password + valid new password → Success

2. Invalid Current Password:
   - Wrong current password → Error: "Current password is incorrect"

3. Same Password:
   - New password same as current → Error: "New password must be different"

4. Validation Errors:
   - New password < 6 chars → Validation error
   - New password > 100 chars → Validation error
   - Empty fields → Validation error

5. Password Mismatch:
   - New password ≠ Confirm password → Frontend validation error

6. Authentication Errors:
   - No token → Redirect to login
   - Expired token → Redirect to login
   - Invalid token → Redirect to login

7. Network Errors:
   - No internet → Show network error
   - Server down → Show server error

8. Edge Cases:
   - Submit while loading → Prevent duplicate submission
   - Navigate away during submission → Handle cleanup
   - Token expires during submission → Handle gracefully
